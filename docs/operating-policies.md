# Operating policies

## Workforce proposal order

Before proposing an agent, evaluate: existing artifact; authoritative retrieval;
deterministic rule; existing script/tool/workflow; extension of an existing
tool/workflow; existing agent; external API/service; ephemeral agent; persistent
agent/team; human escalation.

Every hiring proposal records the gap, insufficiency analysis, outcome, cost,
role, tools/data, authority, model qualifications, evaluation suite,
escalation behavior, and promotion/merge/retirement conditions. The proposer
cannot approve the candidate's authority.

## Legal identity and naming

ARTJ LLC is the planned New York legal container for banking, EIN, taxes,
contracts, payment processors, shared IP, and early operations. Product,
storefront, website, and repository names are not legal entities by default.
The system must distinguish ARTJ LLC from “Agent Foundry,” which is a
technical/repository name only, and must flag persistent non-legal business
names for New York assumed-name review.

The public disclosure default is:

> © 2026 ARTJ LLC. This website/shop is owned and operated by ARTJ LLC.

No agent may form an entity, file an assumed name, register for tax, sign a
contract, open an account, authorize a payment, or publish a legal disclosure
as a production write without a registered tool, applicable policy, and human
approval.

## Automation compiler

Repeated successful agent paths become proposals for deterministic replacement.
Generated code must pass tests, policy review, and shadow comparison before
activation.

## Stacked OODA loops

Company, business-unit, harness, objective, workflow, and agent operations run
as nested Observe/Orient/Decide/Act loops. Each loop has an owner, cadence,
evidence, decision record, action status, and review outcome. A child loop may
not silently change a parent loop's policy, authority, budget, or approval
requirements.

## Harness boundary

Codex and OpenCode are harnesses, not trusted tool gateways. Harness adapters
are experimental and receive only scoped context and read-only tools. Payment,
publishing, advertising, permissions, credential access, and other risky
actions must be proposed to the deterministic tool gateway.
